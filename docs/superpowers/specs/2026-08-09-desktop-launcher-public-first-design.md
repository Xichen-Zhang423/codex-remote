# Codex Remote 桌面启动面板与公网优先连接设计

日期：2026-08-09
状态：已确认（方案 A）

## 目标

让 `start.bat` 启动 Codex Remote 后，自动打开一个无普通浏览器地址栏的独立桌面控制台。控制台默认只展示公网远程连接；局域网地址和二维码仅在用户主动点击连接选项后临时出现。

## 用户体验

1. 用户双击 `start.bat`。
2. 启动器继续负责 Node/npm 检查、用户目录运行时准备和服务启动。
3. HTTP 服务开始监听后，Codex Remote 自动用 Edge 或 Chrome 的应用模式打开本机控制台；若两者都不可用，则使用系统默认浏览器。
4. 控制台首先显示“正在建立公网连接”。Cloudflare Quick Tunnel 上线后，控制台自动生成并显示公网二维码、公网地址和复制按钮，无需用户再次点击。
5. 控制台默认不显示局域网 IP、Wi-Fi 提示或局域网二维码。
6. “连接选项”中提供“显示局域网连接”按钮。只有点击后，才生成并显示当前局域网二维码；该选择仅对当前页面有效，刷新或下次启动后重新隐藏。
7. 关闭桌面控制台窗口不停止后端服务。用户可点击控制台中的“安全停止服务”，或关闭 BAT 窗口/运行停止脚本。

## 方案选择

采用浏览器应用模式，不引入 Electron。

- 相比 Electron，不增加大型运行时、安装步骤、签名和进程清理负担。
- 相比仅在终端打印链接，应用模式提供真正独立、易识别的桌面界面。
- 复用已经存在的 `panel.html`、面板权限和服务状态接口，变更范围集中且可测试。

## 架构与组件

### 桌面窗口启动器

在独立模块中实现桌面面板打开逻辑，服务监听成功后由 `server.js` 调用。

- Windows 按顺序检查 Edge 和 Chrome 的常见安装路径。
- 找到浏览器时，以参数数组调用 `--app=<panelUrl>`，不得把包含面板权限的 URL 拼接进 shell 命令。
- 找不到支持应用模式的浏览器时，直接调用系统 URL 打开器。
- 子进程与服务解耦，关闭面板不会结束服务。
- `NO_PANEL=1` 时不自动打开，供 CI、服务器和故障排查使用。
- 打开失败只记录经过脱敏的诊断，不得使 Codex Remote 启动失败。

### 面板连接模式

面板连接接口接受明确模式：

- `remote`：只使用当前公网隧道地址。隧道尚未上线时返回可识别的“公网连接尚未就绪”，绝不退回局域网。
- `lan`：只使用当前局域网地址，仅响应用户主动触发。

`remote` 是缺省模式，以兼容没有请求体的旧面板调用。未知模式返回 400，不生成连接链接。

### 公网优先界面

面板将连接区域改为主视觉区域：

- 公网隧道未就绪：显示明确的等待状态、动态状态指示和故障提示。
- 公网隧道上线：自动请求一次 `remote` 连接，展示二维码、脱敏后的地址和复制按钮。
- 隧道地址变化：根据 `tunnelOrigin` 变化自动重新生成公网二维码。
- 请求失败：保留面板和停止服务功能，显示可恢复错误，并允许刷新重试。
- 局域网入口放在折叠的“连接选项”中，点击后请求 `lan` 连接并显示独立二维码；再次点击可隐藏。

现有服务、Codex、工作目录、可选工具和诊断信息继续保留，但删除默认可见的“局域网”状态卡片。公网状态仍可见。

### 终端输出

BAT 窗口保留安装、启动、错误和关闭日志，但不再自动打印局域网 URL 或局域网二维码。公网入口由桌面控制台主展示；终端可保留不含访问 token 的公网基础 URL，便于排障。

## 数据流

1. `server.js` 建立本机 HTTP 服务并创建只驻留内存的面板权限。
2. 服务调用桌面窗口启动器，打开带 fragment 权限的面板 URL。
3. `panel.js` 立即从 fragment 读取权限并清理地址栏。
4. 面板轮询只含允许字段的状态接口。
5. 发现 `tunnelOrigin` 上线或变化后，面板向连接接口提交 `{ "mode": "remote" }`。
6. 用户点击局域网选项时，面板提交 `{ "mode": "lan" }`。
7. 后端按模式选择唯一来源，拼接手机访问 token，生成短时展示结果和二维码。

## 安全边界

- 面板权限继续使用 256 位随机值，只放在 URL fragment 中，并在页面加载后立即清除。
- 状态接口不返回手机访问 token，二维码和可复制完整地址只由经授权的 POST 请求生成。
- 公网请求不得静默降级为 LAN，避免用户误以为二维码可在外网使用。
- 浏览器启动必须使用参数化进程调用，不允许 URL 参与命令字符串拼接。
- 日志、错误和诊断继续执行 token、Bearer 和 API key 脱敏。
- 二维码仅在本机面板中显示，不写入仓库、配置文件或持久日志。

## 错误处理

- 隧道初始化中：返回稳定的未就绪状态，面板继续轮询。
- `cloudflared` 缺失或退出：公网卡片显示诊断和重试状态，不自动展示 LAN。
- QR 渲染失败：仍提供可复制地址，并显示脱敏后的错误。
- 浏览器应用模式无法启动：回退默认浏览器；全部打开方式失败时仅写诊断，服务仍保持在线。
- 局域网地址不可用：只在用户打开局域网选项后显示错误。

## 测试与验收

按测试驱动方式完成以下验证：

1. 面板会话把 `remote`/`lan` 模式传给连接提供器，拒绝未知模式。
2. 公网模式未就绪时不会产生或退回局域网 URL。
3. 局域网 URL 只有显式 `lan` 请求才会生成。
4. 面板默认不包含可见局域网地址或二维码，并会在公网隧道上线后自动请求公网连接。
5. 隧道 URL 变化时只重新生成必要的公网二维码，不在每次轮询重复生成。
6. Windows 启动器优先使用 Edge/Chrome 应用模式，参数不经过 shell；失败时执行安全回退。
7. `NO_PANEL=1` 禁止自动打开窗口，打开失败不影响服务。
8. 终端不再输出局域网二维码或带 token 的局域网地址。
9. 完整 `npm run verify`、独立发布副本验证和 GitHub Windows CI 全部通过。
10. 实际启动检查应用模式窗口、默认公网状态、局域网按需显示、复制按钮和安全停止按钮。
