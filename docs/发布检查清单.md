# Codex Remote 发布检查清单

本清单面向准备 GitHub Release 的维护者。自动化门禁可以重复执行；涉及真实 Codex 账号、第二台设备、浏览器安装体验或平台签名的项目必须人工验收，未实际完成前保持未勾选。

## 自动化门禁

在独立仓库根目录的 PowerShell 中依次运行：

```powershell
npm ci --no-audit --no-fund
npm run verify
npm run release:verify
npm run release:copy
npm run release:verify -- --history
```

所有命令必须以 0 failures 结束，严格发布验证打印 `[release] OK`。历史扫描发现问题时只能显示提交哈希、相对路径和规则 ID，不能输出凭据或命中证据正文。

自动化完成后还应确认工作树干净，并阅读本次差异。不要把 `config.json`、`node_modules`、运行时缓存、日志、截图、签名材料或安装构建目录放入发布提交。

## 人工验收

- [ ] `npx --yes --package @openai/codex@0.144.1 codex login status` 成功；真实任务可发送、流式显示、批准、拒绝、中断和恢复。
- [ ] App Server 异常退出后按封顶退避恢复，旧请求不会污染新进程。
- [ ] 二维码渲染失败时仍显示可复制地址；局域网可用，隧道失败不影响局域网。
- [ ] TXT、PNG、PDF 可以预览；HTML、ZIP 只下载；第二台设备重新连接后恢复产出元数据。
- [ ] 320、360、390、430 手机视口、844 横屏、1280 与 1440 桌面视口均无页面横向溢出、遮挡或小于 44 像素的关键触控目标。
- [ ] 离线 PWA 外壳可以打开；重新扫码后能够替换后端连接。
- [ ] GitHub Actions 生成可下载的 Debug APK；发布说明没有把它称为签名包或商店版本。
- [ ] HarmonyOS NEXT 教程可以复现 Web 资源同步与手工签名；仓库中没有证书、私钥、密码或生成工程。
- [ ] `package.json` 与 `CHANGELOG.md` 的版本均为 `0.1.0`；发布说明不包含不存在的 GitHub 地址。
- [ ] Windows 10/11 的非管理员用户可从只读源码启动用户本地运行时，并能通过停止脚本干净退出。

## 不在本次发布范围

签名商店包、原生 iOS、Electron、MSIX、npm 发布和自动创建 GitHub 仓库均不在 `0.1.0` 的发布范围。相关人工验收没有完成时，不得在发布说明中暗示已经交付。
